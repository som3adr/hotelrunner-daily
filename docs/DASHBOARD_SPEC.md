# Dashboard Specification

## Overview

The HTML dashboard is generated by `build_dashboard_html()` in
`hotelrunner_daily_summary.py` and deployed to GitHub Pages via
`.github/workflows/daily_summary.yml`.

It is regenerated every time the workflow runs (every hour).

---

## Layout Structure

```
Header
  ├── Title: "Daily In-House Dashboard"
  ├── Generated timestamp
  └── Run status badge (READY / CHECK FIRST)

Left sidebar: Day navigation
  ├── Each day button: day name, date, arrivals/departures badge, guest count
  └── Today highlighted (emerald green)

Main content area (changes per selected day):
  1. Date header
     └── Alert badges: Conflicts | Blocks | Bed requests | Transfers
  2. Stats row
     └── In-house / Arrivals / Departures / Occupied rooms
  3. Meals & Dinner Preparation
     ├── Breakfast / Lunch / Dinner counts
     ├── Per-house dinner breakdown (Olas: N | Tide: N | Sunrise: N)
     ├── Dinner setup notice (amber banner if 14–24, red if >24)
     └── Expandable audit trail (who counts and why)
  4. Transfers
     ├── Per-transfer card: direction badge, status badge, guest name, details
     ├── Pre-formatted French driver message (copyable)
     └── "Copy Driver Text" button per transfer
  5. Team Message (copyable textarea — DO NOT MODIFY FORMAT)
  6. Arrivals list
  7. Departures list
  8. In-house guests (collapsible)
  9. Room/bed disposition (collapsible)
  10. Manual blocks (collapsible)

Footer:
  ├── Audit Results (collapsible by category)
  └── System Health & Engine Status
```

---

## Data Sources per Section

| Section | Engine Used |
|---------|-------------|
| Meals | `meal_engine.compute_meal_entitlements()` |
| Dinner notice | `meal_engine.dinner_preparation_notice()` |
| Transfers | `transfer_engine.build_transfer_records()` |
| Driver message | `transfer_engine.format_driver_message()` |
| Transfer status | `transfer_state.TransferStateStore` |
| Conflicts | `conflict_engine.detect_conflicts()` |
| System Health | `system_health.SystemHealthStore` |
| Team Message | `build_whatsapp_block()` — **DO NOT MODIFY OUTPUT** |

---

## Rules

- Dashboard is **read-only** — no editing of reservation data
- `build_whatsapp_block()` output MUST NOT change (team-facing, copied to WhatsApp)
- Transfer status badges: `needs_info` (gray) | `ready_to_send` (green) | `sent` (blue)
- Dinner setup notice is visual only — does not auto-send anything

---

## Deployment

1. GitHub Actions workflow: `.github/workflows/daily_summary.yml`
2. Runs hourly: fetches data, generates HTML, commits to repo
3. GitHub Pages serves the file as `index.html`
4. **After deployment**: hard refresh (Ctrl+F5) required to see changes
